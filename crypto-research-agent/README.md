# crypto-research-agent

Research- и сигнальный агент по криптовалютному рынку.
Область — этапы 1–2: research и **бумажные** сигналы. Реальная торговля вне области проекта.

Правила проекта зафиксированы в [CLAUDE.md](CLAUDE.md) и обязательны к соблюдению.

## Что агент делает

- читает публичные рыночные данные с биржи (по умолчанию Bybit через ccxt, только read-only эндпоинты);
- хранит свечи, сигналы, бумажные сделки и кривую капитала в SQLite;
- формирует сигналы детерминированной стратегией (референсная — пересечение двух EMA);
- проверяет каждый вход риск-модулем и исполняет сделки в симуляторе с комиссией и проскальзыванием;
- считает метрики бэктеста и показывает результат до и после комиссий;
- собирает новости из RSS и готовит текстовый дайджест через Claude API;
- отправляет уведомления в Telegram и отвечает на `/status`, `/report`, `/stop`.

Чего агент не делает: не отправляет ордера на биржу и не использует LLM при принятии торгового решения.

## Установка

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env   # заполнить ключи
```

Секреты хранятся только в `.env` и читаются через `src/core/config.py`.
Параметры (биржа, символы, комиссии, лимиты риска) — в `config.yaml`.

## Запуск

```bash
python -m scripts.backfill --symbol BTC/USDT --timeframe 1h --pages 5   # история свечей
python -m scripts.run_backtest --symbol BTC/USDT --timeframe 1h         # бэктест и отчёт
python -m scripts.run_paper --symbol BTC/USDT --once                    # бумажный режим
```

## Структура

| Путь | Назначение |
| --- | --- |
| `src/core/` | конфигурация, база, логирование |
| `src/data/` | рыночные данные (ccxt) и новости (RSS) |
| `src/research/` | текстовый research-слой на Claude API |
| `src/strategy/` | базовый класс стратегии и EMA-кроссовер |
| `src/backtest/` | движок бэктеста и метрики |
| `src/paper/` | симулятор исполнения |
| `src/risk/` | лимиты риска |
| `src/bot/` | Telegram-уведомления и три команды |

Бэктест и paper-режим используют один и тот же код стратегии, риск-модуля и брокера.

## Ключевые инварианты

- деньги, цены, объёмы и PnL — только `decimal.Decimal`, в базе хранятся как TEXT;
- время — всегда UTC, в базе timestamp в миллисекундах;
- комиссия тейкера и проскальзывание учитываются всегда и берутся из `config.yaml`;
- позиция без стоп-лосса и тейк-профита не открывается, плечо отсутствует;
- при достижении дневного лимита убытка новые позиции не открываются до следующего дня UTC.
