# Signal Memory — журнал сигналов

Агент ценен не отдельным сообщением, а **накопленной последовательностью**. Один слабый релиз — шум; четыре подряд — смена режима.

## Что фиксировать

Для каждого существенного события:

| Поле | Содержание |
|------|------------|
| `timestamp` | дата и время публикации с часовым поясом |
| `indicator` | показатель или событие |
| `actual` | фактическое значение |
| `forecast` | консенсус |
| `previous` | предыдущее значение и его пересмотр |
| `market_reaction` | движение UST 2Y/10Y/30Y, DXY, USD/JPY, EUR/JPY, S&P, Nasdaq, Gold, Oil, BTC |
| `initial_conclusion` | первоначальный вывод и присвоенный уровень тревоги |
| `follow_up` | дальнейшее развитие событий |
| `verdict` | подтвердился прогноз или нет |

## Формат хранения

Журнал ведётся в рабочем файле сессии или проекта, например `macro-signal-log.md`, по одной записи на событие:

```
## 2026-09-05 08:30 ET — NFP (август)
actual: [ ] | forecast: [ ] | previous: [ ] (пересмотр: [ ])
reaction: 2Y [ ] · 10Y [ ] · 30Y [ ] · DXY [ ] · USD/JPY [ ] · EUR/JPY [ ] · S&P [ ] · Nasdaq [ ] · Gold [ ] · Oil [ ] · BTC [ ]
level: 🟠
conclusion: [первоначальный вывод]
follow_up: [обновления по датам]
verdict: [подтвердился / не подтвердился / открыт]
```

Для машинной обработки допустим параллельный JSONL-файл с теми же полями.

Отдельно ведётся **регистр режима**: дата, режим, вероятности, что изменило оценку. По нему видно, когда именно агент переключил сценарий и был ли он прав.

## Как использовать историю

**1. Последовательности.** Проверяй не отдельное значение, а серию:

```
JOLTS слабый → ADP слабый → Claims растут → NFP слабый
```
значительно важнее одного слабого показателя. Перед выводом всегда смотри, какое место занимает текущий релиз в серии.

**2. Тренды и ускорения.** Считай 3-месячные и 6-месячные аннуализированные темпы, а не только год к году — разворот виден там первым.

**3. Расхождения.** Фиксируй случаи, когда связанные показатели разошлись (household survey против establishment, Caixin против официального PMI, ETF-потоки против цены).

**4. Изменение реакции рынка.** Самый ценный класс наблюдений: одинаковая новость → другая реакция. Сравнивай текущую реакцию с реакцией на аналогичный релиз 1-3 месяца назад. Если рынок перестал реагировать ростом на хорошие новости или падением на плохие — режим меняется.

**5. Проверка собственных выводов.** Через 1-4 недели после сигнала возвращайся к записи и выставляй verdict. Систематические ошибки в одну сторону — повод скорректировать модель, а не замалчивать.

## Правила ведения

- Никогда не удаляй прежний вывод — добавляй обновление с датой.
- После revised data обновляй запись и явно указывай, изменился ли вывод (`source-verification`).
- Повторная публикация той же новости без новой информации в журнал не попадает.
- В каждой регулярной сводке (`global-macro-update`) давай развитие по открытым сигналам прошлого периода.
- Раз в неделю проверяй открытые записи: что подтвердилось, что нет, какие серии сформировались.

## Формат периодического обзора истории

```
🧠 SIGNAL REVIEW — [период]

Открытые сигналы: [перечень с датами и текущим статусом]
Подтвердившиеся: [ ]
Не подтвердившиеся: [ ] — и почему
Сформировавшиеся серии: [например, 4 подряд слабых релиза по труду]
Изменения реакции рынка: [ ]
Корректировка режима: [было → стало]
```
